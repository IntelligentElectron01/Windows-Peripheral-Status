# Decisions

One line each: decision — why.

## 2026-11-25
- **C# + WPF on .NET 10 (LTS, supported to Nov 2028)** — WPF has a built-in Windows 11 Fluent theme with light/dark, so R10 needs no third-party UI library. .NET 8 (already on this PC) went out of support 2026-11-10.
- **Zero third-party packages** — everything is Microsoft .NET + Windows APIs; fewer things to trust (priority 2).
- **Battery read via Windows' own device property (`DEVPKEY_Bluetooth_Battery`), read-only** — it is the same number Windows Settings shows, covers both BLE and classic (hands-free) devices, and never opens a connection to or writes to a device (rule g).
- **Tray icons via Win32 `Shell_NotifyIcon`, icons drawn at runtime** — lets each pinned device show its own number and colour (R2/R3); no icon library needed.
- **Notifications via tray balloon API (shown as Windows toasts)** — works for an unpackaged app without registering anything system-wide.
- **Storage: JSON files in `%LOCALAPPDATA%\BTBatteryIndicator`** — human-readable, per-user, no database dependency.
- **Start with Windows: `HKCU\...\Run` entry** — per-user, no admin (R9). Written only when the user flips the toggle.
- **History chart drawn by hand in WPF** — avoids a charting package.
- **SDK installed as a zip inside the project (`.tools\dotnet`, git-ignored), not system-wide** — no admin prompt, no change to Windows, delete the folder to remove it.
- **Shipping: self-contained single-folder build + `install.ps1`** — a friend needs nothing pre-installed; per-user install, no admin. Unsigned, so SmartScreen may warn (harmless for a build you made yourself; a code-signing certificate costs money).
- **Capabilities used:** read device properties, read/write own files, one HKCU Run value, show notifications. No network, no admin, no Bluetooth radio control.
- **Repo: private GitHub `IntelligentElectron01/BTBatteryIndicator`** — user request; source only, never settings/history data.
- **Controls styled by hand instead of WPF's built-in Fluent theme** — the accent-colour setting must recolour every control, and the built-in theme always uses the Windows accent. (Supersedes the first line's reason; .NET 10 is still the choice for its support window.)
- **Tray icons use the .NET `NotifyIcon` wrapper rather than raw Win32 calls** — same Windows feature underneath, far less code to get wrong (it already handles Explorer restarts).
- **No test framework; tests are a small console program** — a framework would be a third-party download.
- **A device paired over both classic and Low Energy (e.g. a phone) is shown once** — matched by name; the Low Energy value is preferred because it is exact while hands-free is coarse.
- **Polling every 30 seconds** — simple and reliable across sleep/Bluetooth toggles; the read is a few milliseconds.
- **Low-battery alert fires at or below the threshold and re-arms 2 points above it** — stops repeat alerts when a level wobbles at the edge.
- **`--demo` mode with made-up devices and its own data folder** — lets colours and notifications be tested in a minute instead of waiting for real batteries to drain.
- **Pinned devices show in a strip on the taskbar by default (user request); per-device tray icons remain as a setting** — Windows 11 has no supported way to add content to the taskbar, so the strip is an always-on-top window that follows the taskbar. It reads the taskbar's position only and changes nothing in Windows.
- **Strip follows the taskbar through a Windows "this window moved" notification plus a 2-second safety timer** — polling five times a second kept the CPU awake for nothing.
- **Quick scans read only battery and connected state; names and types are cached and re-read every 15th scan** — cut a scan from 45 ms to 3 ms of CPU.
- **Software rendering, non-concurrent GC, Windows language tables instead of ICU, and handing unused memory back after the UI closes** — together took idle RAM in use from 116 MB to about 25 MB. Cost: the flyout takes a fraction of a second longer to open after a long idle.
- **Not done, needs the user's call:** a build that relies on an installed .NET runtime (154 MB on disk becomes about 1 MB, but friends must install .NET first), and a native rewrite without WPF (about 5 MB RAM and 2 MB on disk, but the interface would be rebuilt from scratch and new build tools downloaded).
- **Apple earbud levels come from listening to their Bluetooth broadcast (user approved 2026-11-25)** — Windows holds no level for them. Receive-only: nothing is sent and no connection is made. Matched to the paired device by Apple's product number, then by signal strength.
- **New capability: passive Bluetooth Low Energy scanning** — only while a connected Apple audio device has no level from Windows; 5 seconds per scan until a level is known, then 5 seconds every 2 minutes.
- **The listener calls Windows' built-in advertisement watcher directly instead of using Microsoft's Windows SDK helper package** — that package is an extra download under Microsoft's Windows SDK licence (not an open licence) and adds about 25 MB to the app. Cost: about 250 lines of low-level code that must match Windows' interface layout; checked live against real broadcasts.
- **Earbud icons are drawn in code from basic shapes (head, ear tip, stem; a case with a lid seam)** — Apple's own symbols are Apple-licensed and cannot be shipped, and Windows' icon font has no earbud glyph.
- **Earbud display rules: pair when within 10 points, single bud when one is worn, separate when they differ; the single number used for alerts and history is the worn bud, otherwise the lower bud** — mirrors how Apple devices present it, and the low-battery alert follows the bud that will die first.
- **Scope change: Logitech receiver devices supported (user request and OK, 2026-11-25)** — the user's mouse is a G502 LIGHTSPEED on a USB receiver, which Windows has no battery value for.
- **New capability: sending messages to a device** — the Logitech reader sends "where is your battery feature / what is your name / what is your level" questions (Logitech's HID++ 2.0 format) through the receiver and reads the replies. It sends nothing that changes a setting. It is the only part of the app that transmits to a device, and it has its own off switch (on by default).
- **Asked every 2 minutes, replies tagged with our own software number** — keeps traffic negligible and avoids confusing our replies with Logitech G HUB's.
- **Voltage converted to percent with a standard lithium-cell curve** — gaming mice such as the G502 report millivolts, not a percentage.
- **The strip is never hidden while the taskbar auto-hides; it rides along and is repositioned on every screen frame during the slide** — measured on the user's PC: Windows moves the taskbar in steps about every 31 ms (about 200 ms to appear, 400 ms to hide), so hiding at a threshold caused a blink. The taskbar is also made the strip's owner so Windows keeps the strip in front of it, and the strip hides only when Windows drops the taskbar behind a full-screen app.
- **The flyout stays clear of a visible taskbar** — with auto-hide on, Windows reports the whole screen as free, so the flyout used to cover the taskbar.
- **Embedding the strip inside the taskbar window was tried and dropped** — on this Windows 11 build the taskbar draws over anything placed inside it (see-through and solid variants were both invisible). The strip stays a separate always-on-top window.
- **The strip glides with the taskbar on its own refresh-timed thread, moving at the taskbar's measured speed between its jumps** — measured: the strip used to sit still for the whole slide and jump at the end (up to 68 px off); it now stays within about half a taskbar jump (average 3-4 px) in both directions. Three causes were fixed: the 'taskbar moved' notification was filtered to the wrong thread, each move waited on Explorer because of window re-ordering, and the app's drawing loop sleeps while the strip is off screen.
- **Sleeping receiver devices keep their last level for 45 minutes and never raise a 'disconnected' alert** — an idle Logitech mouse stops answering within about a minute; that is sleep, not a disconnect.
- **Pinned devices stay listed (as not connected) while they are away** — otherwise a pinned device that is off at start-up vanished from the strip.
- **Click-to-connect (user request, 2026-11-25)** — clicking a pinned device that is not connected asks Windows to connect it, using the same driver request as Windows' own Connect button. Audio devices only; others reconnect by themselves. New capability: changes a device's connection state, only on an explicit click. Verified live: the user's earbuds connected.
- **Installed copy with Start Menu and desktop shortcuts; every package build updates and restarts it (user request)** — no update checker runs inside the app, so there is no background cost and still no network access.
- **Optional keyboard shortcut to open the flyout (user request, 2026-11-25)** — registered with Windows as a system-wide hotkey, so Windows delivers the key press and the app never watches the keyboard. Must include Ctrl, Alt or Win; off by default; if another app already owns the combination the picker says so.
- **A click on a strip item that cannot be connected on request (mouse, keyboard, controller) opens the flyout** — found in testing: with every pinned device disconnected there was no way to open the flyout from the strip.
- **Accent colour is a setting (default blue `#2F7FDB`, or Windows accent)** — user request.
- **The shortcut recorder takes key presses before Windows acts on them (user request, 2026-11-25)** — a keyboard capture is installed only while the recorder is waiting for a combination and removed when it ends, so pressing e.g. Win+E records it instead of opening Explorer. Outside recording the app still never watches the keyboard.
- **The strip is put back in front whenever Windows re-orders the taskbar and after each slide (2026-11-25)** — user report that the strip was sometimes missing; previously only a 2-second safety timer restored it, and not during a slide.
- **The taskbar is the strip's owner again (2026-11-25)** — found on the user's PC: while Start is open Windows lifts the taskbar into a window layer above every ordinary always-on-top window, which covered the strip. An owned strip is carried into that layer with it. Measured after the change: strip visible with Start open, and it strays at most 8 px from the taskbar during a slide.
- **The strip is brought to the front the instant another window takes focus or the taskbar is re-ordered (2026-11-25)** — user report of a half-second pop-in when the Windows key opens Start; before, the strip waited for the slide to finish.
- **Connect popup at the top centre of the screen (user request, 2026-11-26)** — compact dark pill, all non-hidden Bluetooth devices, never devices on a USB receiver (user's choice: they reconnect on every wake). It is suppressed only for exclusive full-screen games and presentation mode; Windows' looser "busy" state was true on the user's PC during ordinary use, so it is ignored. The window exists only while showing.
- **UI screenshots in the repo are generated from demo devices** — `docs/screenshots`, made by `build.ps1 shots`, so no real device names appear.
- **Connect / Disconnect in the device menu (user request, 2026-11-26)** — same Windows Bluetooth-audio request as click-to-connect, with the "disconnect once" code; audio devices only, since Windows offers no supported way to drop other kinds without touching the pairing. Never done by the app on its own.
- **Connect / Disconnect now reach both audio connections (2026-11-26)** — user report: Disconnect failed for earbuds. Only the music connection carries the Bluetooth address; the calls (hands-free) connection does not, so it was missed and Windows kept the device connected. It is now matched by Windows' container id for the same device.
- **Disconnect waits up to 16 seconds before reporting failure (2026-11-26)** — measured on the user's earbuds: Windows accepted the request at once but took about 5 seconds to report the link gone, longer than the 6 seconds the app allowed once its own re-reads were counted, so a working disconnect was reported as failed.
- **Disconnect also closes the radio link (2026-11-26, user asked for a faster disconnect)** — after the two audio connections are told to close, the app asks the PC's Bluetooth radio to close its link to the device. Measured on the user's earbuds: gone in 0.5 seconds instead of about 5, and still disconnected 45 seconds later. No new permission and no admin; the device stays paired. If the radio refuses, Windows still drops the link by itself as before.
- **Clicking a connected audio device on the strip switches the sound output (user request, 2026-11-26)** — only when two or more Bluetooth audio devices are connected and the clicked one is not already playing; otherwise the click opens the flyout as before. Windows has no published call for choosing the output, so the app uses the unpublished one that Windows' own sound panel and most audio switchers use. It changes a Windows sound setting, which the user asked for; it happens only on the user's click.
- **Low-battery warnings use the drop-down pill (user request, 2026-11-26)** — instead of a Windows notification. If popups are being held back for a full-screen app, the warning goes to Windows notifications instead so it is not lost. Disconnect notices and error messages stay as Windows notifications.
- **"Hide popups in full-screen apps" setting, on by default** — a window counts as full screen when it is exactly the size of its screen; an ordinary maximised window is a few pixels larger on each side, which also keeps the rule correct with an auto-hiding taskbar. Exclusive full-screen games and presentation mode are never drawn over, whatever the setting.
- **Smoother popup motion (user report of slight stutter, 2026-11-26)** — measured with a frame timer in demo mode. Causes found and fixed: motion was capped at 60 frames a second on a 165 Hz screen (now the screen's own rate); text and shapes were re-drawn every frame (now drawn once into a picture that is moved); the pill was clipped by the edge of its own window while entering, which made the first 70 ms uneven (the window now extends above the screen so the screen edge does the clipping); and the first frames of a new movement come slowly (the drop now has an unseen 180 ms lead-in). Result: 85 to 89 frames per 0.55 s drop with no frame over 11 ms in most runs, against about 33 frames before. Drawing on the graphics card was tried and rejected: no smoother, and about 70 MB more memory.
- **Hover labels on the strip sit centred above the item** — the default position put them off to the side, over the tray icons.
- **Memory is handed back to Windows after the last popup closes** — same clean-up as after the panel closes; found in the 2026-11-26 resource audit, where RAM in use stayed about 20 MB higher after popups and hover labels.
- **Memory clean-up repeats every ten minutes while no window is open (user request, 2026-11-26)** — the regular scans pulled RAM in use from 33 MB up to 42 MB within four minutes; the clean-up itself costs a few milliseconds.
- **The strip steps aside whenever a full-screen app is in front, also with an auto-hiding taskbar (bug fix, 2026-11-26)** — a full-screen app can cover the taskbar while it is still up instead of making it slide away; the strip, being always on top, was left floating over the app. Reproduced with a full-screen test window. It comes back when the app is no longer in front or Start is opened.
- **Clicking a connected audio device on the strip switches the sound to it from any current output (user request, 2026-11-26)** — replaces the "two or more Bluetooth audio devices" condition, which did nothing when sound was on the PC speakers. If the device is already the output, the click opens the flyout.
- **A pill for every change of sound output or microphone (user request, 2026-11-27)** - Windows tells the app when the default output or microphone changes, so nothing is polled and it costs nothing while idle. Reads only; no new capability. Wording is "Output set" / "Input set". Built-in speakers are recognised by carrying the PC's own device number and shown as "Laptop speakers" with a laptop icon when the PC has a battery.
- **No output or input pill straight after a "Connected" pill for the same device** - a connecting headset becomes output and microphone in the same moment; three pills in a row for one event would be noise. Changes made any other way always show.
